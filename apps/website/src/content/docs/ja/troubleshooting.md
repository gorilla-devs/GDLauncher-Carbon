## アプリのデータパス

GDLauncher が Electron のデータを保存する場所であり、デフォルトでは Core Module のランタイムパスもここに置かれます。

### Windows

`C:\Users\\{{ユーザー名}}\\AppData\Roaming\gdlauncher_carbon`

### macOS

`/Users/{{ユーザー名}}/Library/Application Support/gdlauncher_carbon`

### Linux

- 環境変数 `$XDG_DATA_HOME` が設定されている場合: `$XDG_DATA_HOME/gdlauncher_carbon`
- それ以外: `{{homedir}}/.local/share/gdlauncher_carbon`

[homedir の詳細はこちら](https://nodejs.org/api/os.html#oshomedir)

## Core Module ランタイムパス

Core Module がすべてのデータ（インスタンス、アセット、ライブラリなど）を保存する場所です。
明示的に別の場所を指定しない限り、アプリのデータパスと同じ場所の `data` フォルダーに置かれます。

### アプリデータベース

アプリデータベースは Core Module のランタイムパス内に置かれており、`gdl_conf.db` という名前の SQLite データベースファイルです。

**このファイルには機密情報が含まれているため、絶対に他人に送らないでください。**

### アプリログ

GDLauncher はアプリレベルのログを 2 つのファイルに書き込みます。サポートには **常に両方** を送ってください。ランチャーの 2 つのプロセスは互いに作業を引き継ぐため、一方の障害の原因がもう一方のログに現れることが多いためです。

- **`main.log`** (App Data Path 内): Electron メインプロセスのログ。ウィンドウ生成、IPC、自動更新、ネイティブダイアログ、デスクトップシェルのハードクラッシュなどを記録。
- **`__gdl_logs__/<timestamp>.log`** (Core Module Runtime Path 内): Rust コアのログ。アカウントサインイン、アセットダウンロード、Mod ローダーのインストール、インスタンス起動、設定変更などを記録。最新 10 件を保持。

OS 別のパスやスクリーンショットは [Share App Logs](/guides/share-app-logs) を参照。

**ログには機密情報が含まれることがあります。共有時はご注意ください。**

### ランタイムパスの変更

ランタイムパスを変更すると、アプリはすべてのインスタンスと設定ファイルを自動的に新しい場所へ移動します。

移行先のフォルダーがすでに使用されている場合、アプリはランタイムパス設定を切り替えるだけで、ファイルの移動やコピーは行いません。

#### 移行エラー

移行に失敗すると、アプリはエラーメッセージを表示します。

エラーメッセージで失敗した段階を確認してください。移行先の内容と、再起動後にランチャーが実際に使用するランタイムを確認するまで、旧ランタイム、移行先、復旧用コピーをすべて保存してください。コピー完了はパスのポインター公開を意味しません。旧バージョンでは後続の失敗で移行先のコピーがロールバックされることがあり、そこで移行元を削除すると唯一使えるコピーを失う可能性があります。

**再起動後も Settings → Runtime Path に旧パスが表示されている場合**、移動は完了前に止まっており、データは旧パスに安全に残っています。ランチャーは新しいフォルダーにコピーしたものを削除するので、エラーに示された原因を解消し (例: 移動先ドライブの空き容量を増やす)、同じパスまたは別の空のフォルダーへもう一度移動してください。一部のファイルを削除できなかった場合 (別のプログラムが開いていた場合など) は、新しいフォルダーにそれらが残り、`.gdl_migration_in_progress` ファイルで印が付きます。ランチャーはこのフォルダーを使わず、再びここへ移動することもしません。Settings でこのフォルダーを選ぶと、途中で止まった移動のフォルダーだと表示されます。このフォルダーを削除してから、もう一度移動してください。

ランタイムポインターの公開前に移動が失敗した場合、現在のランチャーは移行先にコピーしたデータを削除します。削除できなかったものは `.gdl_migration_in_progress` の印とともに残り、旧ランタイムが選択されたままになります。ポインター公開後は明示的な上書き設定が優先される場合を除き移行先が選択され、後続の警告でロールバックされません。その後、ランチャーは各ファイルがコピーと一致していることを確認してから旧ランタイムの元ファイルを削除するため、移動によって旧ドライブの空き容量が増えます。コピー後に変更されたファイルは旧ランタイムに残ります。削除できなかったファイル (別のプログラムが開いていた、または権限がない) も同様です。ランチャーはいずれの場合も再起動し、新しい場所からの最初の起動時にそれらのファイルを 2 つのグループに分けて一覧表示します。変更されたファイルは新しい場所のコピーより新しい可能性があります。必要な場合は、プレイする前に新しい場所の同じ位置へコピーしてください。削除できなかったファイルはコピーと同じ内容なので、削除してかまいません。新しい場所がディスクに保存されたことを確認できない場合、ランチャーは何も削除せず、再起動後にそのことを知らせます。インスタンスが新しい場所にあることを確認したら、旧フォルダーを削除してかまいません。

`runtime_path_override` は旧ランタイムではなく、Electron の `userData` ディレクトリ（ランチャーのアプリデータ）にあります。保存してください。明示的なコマンドラインのランタイムパスは環境変数のパスより優先され、どちらもこのポインターより優先されます。ランチャーのランタイムパス設定で実際の場所を確認してください。復旧ダイアログが Restart または Retry を要求する場合はその操作に従い、再び失敗しても両方のフォルダーを保持してください。

ご不明な点があれば、[Discord サーバー](https://discord.gdlauncher.com) に参加してご質問ください。
