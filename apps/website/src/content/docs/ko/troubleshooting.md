## 앱 데이터 경로

GDLauncher가 Electron의 데이터와 기본적으로 Core Module 런타임 경로를 저장하는 경로입니다.

### Windows

`C:\Users\\{{사용자 이름}}\\AppData\Roaming\gdlauncher_carbon`

### macOS

`/Users/{{사용자 이름}}/Library/Application Support/gdlauncher_carbon`

### Linux

- `$XDG_DATA_HOME` 환경 변수가 설정된 경우: `$XDG_DATA_HOME/gdlauncher_carbon`
- 설정되지 않은 경우: `{{homedir}}/.local/share/gdlauncher_carbon`

[homedir 자세한 내용](https://nodejs.org/api/os.html#oshomedir)

## Core Module 런타임 경로

Core Module이 모든 데이터(인스턴스, 에셋, 라이브러리 등)를 저장하는 경로입니다.
일반적으로 앱 데이터 경로의 `data` 하위 폴더에 위치하며, 다른 위치를 직접 지정한 경우는 예외입니다.

### 앱 데이터베이스

앱 데이터베이스는 Core Module 런타임 경로에 위치하며, `gdl_conf.db`라는 SQLite 데이터베이스 파일입니다.

**이 파일에는 민감한 데이터가 포함되어 있으므로 누구에게도 보내지 마세요.**

### 앱 로그

GDLauncher는 앱 레벨 로그를 두 개의 파일에 기록합니다. 지원 요청에는 **항상 둘 다** 보내세요. 런처의 두 프로세스는 서로 작업을 주고받기 때문에 한쪽의 실패 원인이 다른 쪽 로그에 나타나는 경우가 많습니다.

- **`main.log`** (App Data Path 내): Electron 메인 프로세스 로그. 창 생성, IPC, 자동 업데이트, 네이티브 다이얼로그, 데스크톱 셸의 하드 크래시 등을 기록.
- **`__gdl_logs__/<timestamp>.log`** (Core Module Runtime Path 내): Rust 코어 로그. 계정 로그인, 에셋 다운로드, 모드 로더 설치, 인스턴스 실행, 설정 변경 등을 기록. 최신 10개 유지.

OS별 경로와 스크린샷은 [Share App Logs](/guides/share-app-logs)를 참고.

**로그에는 민감한 데이터가 포함될 수 있으므로 공유 시 주의하세요.**

### 런타임 경로 변경

런타임 경로를 변경하면, 앱이 모든 인스턴스와 설정 파일을 새 위치로 자동으로 이동시킵니다.

대상 폴더가 이미 사용 중이라면, 앱은 런타임 경로 설정만 전환하고 어떤 파일도 이동하거나 복사하지 않습니다.

#### 마이그레이션 오류

마이그레이션이 실패하면 앱이 오류 메시지를 표시합니다.

오류 메시지에서 실패한 단계를 확인하세요. 대상 데이터와 재시작 후 런처가 실제로 사용하는 런타임을 모두 확인할 때까지 이전 런타임, 대상 폴더, 복구 사본을 보존하세요. 복사 완료는 경로 포인터가 게시되었다는 증거가 아닙니다. 이전 버전은 이후 단계의 실패로 대상의 복사 파일을 롤백할 수 있었으므로, 이때 원본을 삭제하면 유일한 사용 가능한 사본을 잃을 수 있습니다.

**재시작 후에도 Settings → Runtime Path에 옛 경로가 표시된다면**, 이동이 끝나기 전에 멈춘 것이고 데이터는 옛 경로에 안전하게 남아 있습니다. 런처는 새 폴더에 복사했던 것을 지우므로, 오류에 나온 원인을 해결하고(예: 대상 드라이브의 공간 확보) 같은 경로나 다른 빈 폴더로 다시 이동하세요. 일부 파일을 지우지 못했다면(예: 다른 프로그램이 열어 둔 경우) 새 폴더에 그 파일이 남고 `.gdl_migration_in_progress` 파일로 표시됩니다. 런처는 이 폴더를 사용하지 않고 다시 이 폴더로 이동하지도 않으며, Settings에서 이 폴더를 고르면 끝나지 않은 이동이라고 알려 줍니다. 이 폴더를 지운 뒤 다시 이동하세요.

런타임 포인터를 게시하기 전에 이동이 실패하면 현재 런처는 대상에 복사한 데이터를 지웁니다. 지우지 못한 것은 `.gdl_migration_in_progress` 표시와 함께 남고, 이전 런타임이 계속 선택됩니다. 포인터 게시 후에는 명시적 경로 재정의가 우선하는 경우를 제외하고 대상이 선택되며, 이후 경고로 롤백하지 않습니다. 그 후 런처는 각 파일이 사본과 여전히 일치하는지 확인한 뒤 이전 런타임의 원본을 삭제하므로, 이동하면 이전 드라이브의 공간이 확보됩니다. 복사 후 변경된 파일은 이전 런타임에 남으며, 삭제할 수 없었던 파일(다른 프로그램이 열어 두었거나 권한이 없는 경우)도 마찬가지입니다. 런처는 어느 경우든 재시작하고, 새 위치에서 처음 시작할 때 이런 파일을 두 그룹으로 나누어 보여 줍니다. 변경된 파일은 새 위치의 사본보다 새로울 수 있으므로, 필요하면 플레이하기 전에 새 위치의 같은 자리로 복사하세요. 삭제하지 못한 파일은 사본과 같으므로 삭제해도 됩니다. 새 위치가 디스크에 저장되었는지 확인할 수 없으면 런처는 아무것도 삭제하지 않고 재시작 후 그 사실을 알려 줍니다. 인스턴스가 새 위치에 있는지 확인한 뒤에는 이전 폴더를 삭제해도 됩니다.

`runtime_path_override` 포인터는 이전 런타임이 아닌 Electron의 `userData` 디렉터리(런처 앱 데이터)에 있습니다. 보존하세요. 명시적 명령줄 런타임 경로가 환경 변수 경로보다 우선하며 둘 다 포인터보다 우선합니다. 런처의 런타임 경로 설정에서 실제 위치를 확인하세요. 복구 대화상자가 Restart 또는 Retry를 요구하면 해당 작업을 따르고, 다시 실패해도 두 폴더를 보존하세요.

실제 포인터의 위치는 [마커와 앱 데이터 위치](/ko/docs/runtime-path-vs-app-data#runtime_path_override-마커)를 참고하세요.

확신이 서지 않으면 [Discord 서버](https://discord.gdlauncher.com)에 참여하여 도움을 요청하세요.
